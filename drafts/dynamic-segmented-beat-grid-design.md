# 动态多 clip 网格功能规范

维护状态：已实现，持续维护

创建日期：2026-07-04

验收入口：[动态多 clip 网格功能验收速查](./dynamic-segmented-beat-grid-test-checklist.md)。本文定义长期产品语义和架构边界，不记录某次实现过程、临时排查或测试结果。

## 1. 功能范围

动态多 clip 网格用于歌曲在不同时间段需要不同 BPM 或相位的网格定义。人工编辑为既有能力；自动 Dynamic 分析作为实验模式在 RC 和开发环境开放，标定与完整验收计划见[自动分析方案](./dynamic-grid-analysis-minimal-plan.md)。

- 当前有效网格统一以规范化的 `SongBeatGridMapV2` 为事实源；固定 BPM 对应单 clip，固定播放与分析行为沿用原路径。
- 人工编辑或通过整曲质量检查的 Dynamic 分析均可形成多个有效 clip；数据结构使用 `SongBeatGridMapV2`。
- 动态歌曲以完整 `beatGridMap` 为网格事实源；旧字段只是兼容摘要，取第一段的投影，不能取平均 BPM、最长段 BPM 或当前播放段 BPM。
- 动态网格必须在普通播放、编辑、双轨同步和 Mixtape 中使用同一份时间解释，不能在任何一处悄悄退化为第一段固定 BPM。

## 2. 数据不变量

`beatGridMap` 保存连续虚拟固定 BPM clip 的边界、锚点、BPM 和相位；不保存每根拍线、UI 选中状态或临时编辑范围。clip 的右边界由下一段起点或歌曲结尾推导。

- 首段从歌曲时间线 `0` 开始，后续 `startSec` 严格递增，且必须落在可靠的歌曲时长内。
- 相邻 BPM 和相位连续的 clip 自动合并；只剩一个有效 clip 时保留规范化的单 clip map，兼容字段由同一份定义投影。
- `signature` 是规范化 clip 的派生缓存，不是事实源；读取、比较和写入都以规范化 clips 为准。
- 无效 map 不得通过旧固定字段重新认定为有效分析结果；保留旧数据并按现有缺失分析处理，禁止静默篡改。
- 复制、内部引用、备份、恢复、扫描和缓存继承都必须保留完整 map。Normal 重新分析沿用固定结果语义；Dynamic 重新分析先计算后替换，失败保留旧定义。后台分析不得覆盖人工网格。

## 3. 编辑语义

编辑模式提供“整首调整”和“从当前点之后调整”两个互斥状态。

- 整首调整移动整首网格相位，不移动边界。
- 从当前点之后调整在播放头创建或选中边界，并只编辑选中 clip 的 BPM、tap BPM 和相位；创建边界本身继承原网格，不能改变声音或画面。
- 靠近现有边界时优先选中边界，不创建极短 clip。边界固定，不支持拖动。
- 删除边界意味着右段并入左段；自然合并成单段时退回固定 BPM，不提供另一套“强制合并为固定”操作。
- 局部调整后落到左边界之前的拍线必须裁剪，不能显示、吸附或参与段落、loop 和 Mixtape 计算。
- 主编辑模式实时生效并去抖保存；Mixtape 中编辑歌曲网格仍保留“应用/取消”两阶段，取消不能影响共享歌曲源网格。

## 4. 显示与基础操作

- 大波形显示完整动态网格，跨 clip 后拍线间距连续改变；clip 边界可见且编辑时可选中。
- 概览和小波形只显示轻量边界提示，不能铺满密集动态拍线。
- 当前 BPM 跟随播放头所在 clip；正在输入 BPM 时不自动切换。列表展示多段 BPM 摘要，筛选按任一 clip 命中，排序按最低 clip BPM。
- Cue、Hot Cue、Memory Cue 和已有 loop 的真实时间点不因网格编辑而移动；它们的拍数、小节等派生标签要刷新。
- Quantize、Beat Jump、Loop 和 Metronome 使用完整动态拍线和累计 beat ordinal；跨 clip 时不能按当前 BPM 加固定秒数。

## 5. 播放、同步和分析

- 普通播放跨 clip 是原音频连续播放，不能 seek、重载或改变播放速度。
- 动态歌曲 BeatSync 使用局部 BPM 与动态 beat ordinal；与固定歌曲混合时仍必须稳定对齐。跨 clip 的同步倍率变化要平滑，不能用可见跳位掩盖。
- 段落分析正在独立重构，其 Dynamic 接口、缓存、重算与联合验收暂缓。本轮 Dynamic 网格任务不触发基于首段投影的段落计算；旧段落处理遵循段落模块自身规则。
- Key 分析不受动态网格影响；不做按 clip 的 Key 分析。
- 自动分析默认 Normal，保持既有固定网格路径。RC 与开发环境均可选 Dynamic，按完整 audio 时间线扫描，结果可为 fixed、dynamic 或明确的未解决/不支持/取消/错误；失败不得静默改存固定首段或 no-bpm。
- Dynamic 结果以完整 map 为准，audio 到 timeline 只转换一次，旧字段始终来自首段投影。请求模式、实际结果形态和 policy 分别记录，不能通过 clip 数反推模式。
- Dynamic 能量使用当前有效完整网格，并绑定源网格签名；人工网格被保护时不能发布基于被拒候选的能量结果。

## 6. Mixtape

动态歌曲进入 Mixtape 后，source beat map、track time map、可见网格、snap、beat align、loop 展开、预览和导出必须共享完整动态映射。

- 动态歌曲在计算层可展开为多个虚拟固定 BPM clip，但库和 UI 中仍是一首歌，播放与导出必须无缝。
- 裁剪起点变化后，锚点 BPM 和缩放按新的起点所在 clip 重算；裁掉的部分不能继续影响自动 tempo 贡献。
- 歌曲移动或删除时，它派生的自动 tempo 贡献同步移动或删除；全局手动 BPM 点优先，且不反写歌曲网格。
- Mixtape 使用歌曲库当前有效源网格，不保存私有快照。源网格改变后刷新派生结果，但只要项目 placement 等项目数据没变，就不应凭此把项目标为 dirty。
- Mixtape 的歌曲网格调整修改共享歌曲源网格；全局 BPM 包络线调整只修改当前项目，两者必须明确区分。

## 7. 外部边界和禁止项

- 不做 Rekordbox beat grid 的导入、写回或动态网格同步；现有歌单写入能力不等于网格写入能力。
- 不做 per-playlist-item 网格 override；同一歌曲实体的内部引用共享同一份网格定义。
- 不因新增 Dynamic 模式改变固定歌曲的正常播放与 Normal 分析结果；单 clip map 沿用现有统一存储契约。
- 不以 UI 网格重合替代声音、同步、跨边界连续性和 Mixtape 导出的真实验收。
